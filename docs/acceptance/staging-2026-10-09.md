## Reproduced defects and fixes

- Auth confirmation only supported token-hash links, excluding default PKCE code callbacks. Both flows are now handled; invalid/expired/provider-error links fail safely.
- Middleware redirects discarded refreshed/deleted session cookies. Redirects now preserve cookies and cache headers. Login return paths reject browser-normalized external redirects.
- Owner suppression RPC failed under RLS because invoker functions lacked write policies. Scoped admin insert/lift policies now work, with an integrity trigger preserving ledger history.
- Live suppression was ignored during approval after the policy-receipt migration. A suppressed synthetic account was reproducibly approved on baseline. Shared approval integrity checks now reject both RPC and direct INSERT bypasses, re-check current recipients, exact proof, source provenance and workspace policy, and preserve blocked-draft rejection.
- Direct approved/sent outreach-state writes were not fully constrained. A held-state integrity trigger requires the exact Owner/Admin decision and rejects sent/provider state.
- Held draft policy receipts were never populated. A database trigger derives them from current stored policy, purpose, region and evidence provenance; caller assertions cannot provide eligibility. Defaults remain blocked until inputs are established.
- Approved proof snapshots used `id` rather than required `proofPointId`. The app now writes the correct exact-claim reference.
- Held Outbox failed reads could masquerade as empty data and missing dependencies disappeared. It now withholds counts/actions and shows incomplete records.
- Settings could suggest required guardrails were optional. Safety requirements remain mandatory; Owner/Admin may record reviewed region policy references and collection purpose. This is product eligibility for human review, not a legal-compliance determination.
